# 生成パイプライン解説

このプロジェクトには DCC ツールで作ったメッシュもインポートしたアニメーションも
ありません。すべての形状は GDScript の演算子の合成で作られています。
本書はその「作り方」を、実際のコードに対応づけて説明します。

---

## 1. 造形の基本演算子（`src/procgen/mesh_lib.gd`）

モデラーが DCC で行う操作を、`Mesh.ARRAY_*` の配列に対する関数として実装しています。
すべて入出力が同じ形式なので、任意に合成できます。

| 関数 | 対応する操作 |
|---|---|
| `tube(control, keys, ...)` | カーブに沿ったロフト（スイープ） |
| `catmull_rom` / `rmf_frames` | パスの再標本化と、ねじれない座標系の生成 |
| `subdivide` | 1→4 の中点細分割（辺の中点を共有） |
| `relax` | ラプラシアン平滑化 |
| `displace(noise, amount)` | 法線方向へのノイズ変位 |
| `weld(epsilon)` | 頂点マージ（ロフトの継ぎ目を滑らかに） |
| `bake_cavity` | 頂点カラーへのキャビティ（曲率）焼き込み |
| `with_lods` | meshoptimizer による離散 LOD 生成 |

### ねじれないロフトが要る理由

`rmf_frames` は二重反射法による **回転最小化フレーム**です。
単純に「接線＋固定 up ベクトル」でフレームを作ると、パスが曲がった箇所で
断面が回転してしまい、腕や尻尾に目に見える捻れが出ます。

### 頂点カラーのキャビティ

`bake_cavity` は隣接頂点との相対位置から凹凸を推定し、頂点カラー R に格納します。
シェーダ側（`skin` / `armor` / `carapace` / `suit`）はこれを

- アルベドの暗部（谷に汚れが溜まる）
- アーマーのエッジ摩耗マスク（尾根＝摩耗する）
- AO の基礎値

として使います。SSAO が効く前段で「プラスチックに見えない」ための下地です。

## 2. 彫刻（`src/procgen/sculpt.gd`）

`blob` / `scale_region` / `crease` / `bend` / `twist` / `flatten_below` は
いずれも **楕円体のフォールオフ（smoothstep）** を重みとして頂点を動かします。
ZBrush の標準ブラシに対応するイメージです。

顔（`head_builder.gd`）はこの演算子だけで、次の順に作られています。

1. UV 球（成人男性頭蓋の平均寸法 195×155×200 mm）
2. 頭蓋の整形（後頭部の突出、頭頂の平坦化、こめかみの窪み）
3. 顔面の平坦化 → 頬骨 → 下顎角
4. 眉弓 → 眼窩の掘り込み → 上下眼瞼の再構築 → 二重の折り目
5. 鼻根 → 鼻背 → 鼻尖 → 鼻翼 → 鼻孔
6. 口輪筋の隆起 → 唇線のクリース → 上下口唇 → 人中 → オトガイ
7. 耳（耳輪・耳甲介・耳垂）
8. 細分割 → 平滑化 → 毛穴ノイズ → しわノイズ → キャビティ焼き込み

## 3. スキニング（`src/procgen/skinning.gd`）

ボーンごとに「線分＋半径」のカプセルを定義し、
頂点からの距離のべき乗フォールオフを重みとします。上位 4 本を正規化して
`ARRAY_BONES` / `ARRAY_WEIGHTS` に格納します。

メッシュ自体が **同じ骨格線分に沿ってロフトされている**ため、
この単純な手法でも実用的な変形が得られます。
アーマーも素体と同じ制御パスから作るので、同じカプセル群でそのまま結合できます。

---

## 4. リグの規約

すべてのリグは **静止姿勢の基底が単位行列**（並進のみ）です。これにより

- ボーンの「向き」＝子ボーンへのオフセット方向
- ボーンを向ける ＝ 最短弧回転を 1 回求めるだけ

となり、`src/player/pose_kit.gd` の `aim()` / `two_bone()` が
補正行列なしで書けます。手続き型アニメーションの可読性はここで決まります。

---

## 5. 歩容モデル（`src/player/animator.gd`）

足先の目標位置を、周期 `t ∈ [0,1)` の関数として定義します。

- `t < 0.62`（スタンス）: 足は接地したまま、body が前進する速度と
  **同じ速度で後方へ**移動する → 足の滑りが原理的に起きない
- `t ≥ 0.62`（スイング）: 前方へ ease し、`sin(πu)` の弧で持ち上げる

この目標を 2 ボーン IK で解き、上に

- 骨盤：1 ストライドあたり 2 回の上下動＋左右のロール＋腰のヨー
- 脊椎：骨盤と**逆位相**のヨー（実際の歩行と同じ）
- 腕：脚と逆位相のスイング、前方で肘がより深く曲がる
- 頭部：前庭動眼反射に相当する水平安定化

を重ねます。四足（`src/ai/monster_animator.gd`）は同じ枠組みで、
位相を対角ペア（斜対歩）にし、前肢は膝が後ろ・後肢は飛節が前に折れるよう
ポールベクトルの符号を変えています。

## 6. 建築（`src/procgen/building.gd`）

- 段（tier）の積み重ねとしてマスを決める（セットバックがスカイラインを作る）
- 壁の UV は **メートル単位**：U は外周に沿った距離、V は基底からの高さ
- 各段の頂部にコーニス（庇）、屋上に設備（空調・貯水槽・アンテナ・パラペット）
- 窓はジオメトリではなく `facade.gdshader` の **インテリアマッピング**

インテリアマッピングは、接空間で視線ベクトルと仮想の部屋ボックスの
スラブ交差を解き、当たった面（奥壁／床／天井／側壁）で色を切り替えます。
1 ピクセルあたり数命令で、視差の正しい室内が得られます。

---

## 7. 素材の解決（`src/core/asset_library.gd`）

ワールド生成側は常に**ロール名**（`asphalt` / `cliff` / `brick` …）で素材を要求します。

1. `assets/polyhaven/manifest.json` に該当スラッグがあれば、その写真測量 PBR を使用
2. なければ `FastNoiseLite` から アルベド／ノーマル／ラフネスを合成して使用

そのため素材未取得でも破綻せず、取得すると同じコードのまま情報量だけが上がります。
